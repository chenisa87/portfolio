## 專案目標

想用對方喜歡的寶可夢當題材，做一個能在手機上玩、玩到最後會變成告白的小遊戲。重點不是複雜的系統，而是**節奏**：前面像正常的對戰，中途慢慢發現「好像哪裡怪怪的」，最後一刻從螢幕走進現實。

## 遊戲流程

1. **訓練家登記**：開場 6 題小問卷（生日、最喜歡的寶可夢……），答案會被記下來，之後出現在對戰台詞和結局裡。
2. **屬性對戰**：雙方各 3 隻原創怪獸，有屬性相剋、會心一擊、麻痺、回復、護盾等機制。招式上會標示「▲ 絕佳／▼ 不佳」，前期要靠屬性取勝。
3. **隱藏招式**：打倒第一隻對手後才解鎖第 4 招「調情技」，此時才揭露訓練家也有一條「心防」血條。
4. **攻擊訓練家**：打倒兩隻對手或用調情技 3 次後，出現「直接對訓練家出招」，心防降到一定程度訓練家還會「假裝冷靜」回血，增加起伏。
5. **收服**：心防歸零後只有 4 顆心之球，而且一定會失敗——第 5 顆球在現實中由我親手交給對方。按下「我丟出去了！」後進入結局與一本會逐字打出來的回憶圖鑑。

## 做法

- **單一 HTML 檔**：所有角色都是手寫的 inline SVG，沒有任何圖片素材，也沒有使用寶可夢官方的圖或音樂（避免版權問題）。
- **狀態機式的回合流程**：用 `async/await` 串起「出招 → 動畫 → 對話框 → 判定倒下／換人」，打字機效果的對話框可點擊加速。
- **8-bit 合成音效**：用 Web Audio API 即時合成背景音樂（四種曲目依劇情切換）與所有音效，沒有載入任何音檔；附靜音鍵並記住設定。
- **平衡測試**：寫了 Playwright 自動化腳本，模擬「只會普攻／只用調情技／亂按」三種玩法，調整解鎖條件與數值，讓每種玩法都落在 20～30 回合，不會太快結束。
- **部署**：GitHub + Cloudflare Pages，push 後自動上線；手機寬度（375px）逐一檢查版面。

## 遇到的問題

- **第二隻怪獸消失**：倒下動畫用了 `fill: 'forwards'`，結束後一直把透明度鎖在 0，新怪獸出場也看不見。改成出場前先 `getAnimations().forEach(a => a.cancel())`。
- **iPhone 靜音模式沒有聲音**：Web Audio 會跟著實體靜音鍵，只能在使用前提醒。
- **部署卡住**：GitHub 事件延遲導致 Cloudflare 組建逾時，手動「重試部署」解決。

## 心得

最花時間的不是程式，而是「什麼時候讓玩家發現下一個秘密」。把解鎖條件從「用 3 次調情技」改成「先打倒一隻對手」之後，整個遊戲的節奏才終於對了。
